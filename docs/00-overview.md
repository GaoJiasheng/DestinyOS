## 0. 一句话定位

**天机（DestinyOS）** 是一个面向海外华人的中英双语在线命理平台：把八字、紫微斗数、周易梅花、奇门遁甲、塔罗、西方占星、吠陀占星、生命灵数八大体系装进一个暗色星空风格的站点，用确定性的排盘引擎和结构化解读知识库，生成清晰易懂、可以深入研读的分析报告，并提供每日运势等日常功能。免费、带广告，付费可去广告。

域名 `tianji.gavin.pub`。中文名「天机」，英文名「DestinyOS」。

## 3. 产品原则（评审任何功能时的标尺）

1. **先排盘，再解读，最后才是花哨。** 排盘必须准确可核验（用户能对照其他排盘网站得到同样结果），解读必须有据可查（每条解读能追溯到知识库单元和触发条件），视觉效果是在这两者之上的加分。
2. **看得懂。** 每一段解读都遵循「结论 → 为什么 → 举例 → 建议」的结构，术语第一次出现时带一行白话解释，不堆古文。古文原文作为可展开的引用出现，不作为正文。
3. **不吓人、不承诺。** 不使用"必有大灾""注定离婚"之类的绝对化、恐吓性措辞；不做医疗、法律、投资建议。所有页面带娱乐性质免责声明。
4. **用户的出生信息是最高敏感等级。** 不进日志、不进分析工具、不进第三方、不进 URL；加密存储；用户可一键删除。
5. **离线可算。** 排盘和解读引擎是纯函数，不依赖网络和数据库，可以在单元测试里完整验证，也能在浏览器端运行。
6. **双语是一等公民。** 任何用户可见文案都同时存在中英版本，缺失任何一边都算 bug。
7. **移动优先。** 所有页面先按 375px 宽设计，再扩展到桌面。

## 4. 术语速查（详见 appendix/glossary.md）

- **体系 System**：八个命理体系之一，代码枚举 `bazi | ziwei | iching | qimen | tarot | astrology | vedic | numerology`。
- **出生档案 BirthProfile**：用户保存的出生信息（日期、时间、时辰是否未知、出生地经纬度、时区、性别）。一期每个账户只有一份。
- **排盘 Chart**：引擎根据输入算出的结构化结果（四柱、十二宫、卦象、九宫、牌阵、行星位置等），是 JSON。
- **解读单元 Knowledge Unit（KU）**：知识库里的最小内容单位，有触发条件和中英文正文。
- **报告 Reading**：一次完整的推算结果快照 = 输入 + Chart + 命中的 KU 列表 + 组合后的文章，持久化并可分享。
- **每日运势 Daily Fortune**：基于用户出生档案与当日时空参数算出的当天报告。
- **流派 School**：同一体系内不同的计算规则（如八字早晚子时、紫微四化派别、占星宫位制）。

## 5. 范围边界

**一期包含**：八大体系的排盘与报告、每日运势、账户与出生档案、分享卡片、AdSense 广告、Stripe 去广告订阅、简单后台、中英双语、PWA。

**一期不包含**（见 14-backlog.md）：多档案与合盘、消息推送、AI 对话追问、面相手相、更多体系（生命灵数已由 B-10 提前实现；六壬、太乙、姓名学、风水、玛雅历等）、原生 App、微信登录与支付。

## 6. 成功标准（一期上线时）

- 原七个体系任选出生信息，排盘结果与至少一个公认参考站点一致（具体对照站点见各体系文档的「核验」一节）；生命灵数按明确的算术规则与独立手算用例核验。
- 每份报告中文 ≥ 2500 字、英文 ≥ 1800 词，并通过 05 文档定义的可读性检查。
- 移动端首页 Lighthouse Performance ≥ 85，Accessibility ≥ 90。
- 新用户从打开首页到看到第一份报告 ≤ 90 秒（无需登录即可试算，登录后保存）。
- 出生信息在数据库中以密文存储，数据库 dump 中不可见明文；日志中不出现出生日期。
- AdSense 审核通过；Stripe 订阅可完成购买与取消。

## 7. 给施工模型的总提示

- 不要为了省事跳过任何一个"状态"（加载、空、错误、未登录、无时辰）。02 文档对每个页面都列了状态，每个状态都要实现。
- 不要改动文档里给出的枚举值、字段名、路由。需要新增时在 PR 描述里说明。
- 任何涉及命理规则的代码必须附带文档中列出的测试用例，测试不过不算完成。
- 遇到文档没有覆盖的细节，优先选"最主流做法"，并在代码注释里写 `// DESIGN-GAP: <说明>`，方便事后回收。
